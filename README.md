# Practice 3. NpcWar

(Made with Deepseek Harness)

Небольшой проект на Godot 4.7 / C#: НПС воюют командами, а игрок наблюдает за сценой свободной камерой.

## Управление

- `WASD` — полёт по направлению камеры.
- `Shift` — ускорение.
- `Мышь` — обзор.
- `Esc` — отпустить мышь, клик — снова захватить.
- `Z` — показать/скрыть розовые полупрозрачные хитбоксы.

## НПС-менеджер

`NpcManager` — отдельный узел сцены. Он:

- создаёт НПС через `Instantiate`;
- хранит ссылки на НПС в массиве;
- выдаёт НПС очки, компоненты и команду;
- спавнит НПС в кольцевых секторах команд;
- хранит ссылки на позиции НПС для движения и выбора цели;
- обновляет Label `Npcs` количеством **не-null** элементов массива НПС.

Очки описаны прямо в менеджере:

```text
Difficulty = points;
interface's upgrade *= 1.2 for every stat;
npc = 2 points;
interface = 3 points;
interface's upgrade = 1 point;
interface can have max 3 upgrades;
```

Компоненты НПС:

- `HealthComponent` — здоровье, защита, регенерация, смерть и вызов `NpcManager.RemoveNpc`.
- `MoveComponent` — движение к цели.
- `ShootComponent` — стрельба пулями.
- `MeleeAttackComponent` — ближний бой.
- `INpcComponent` / `INpcAttack` — общие контракты.

`ShootComponent` принимает сцену пули через `[Export] BulletScene`; если она не задана, ищется `Bullet.tscn`.

## Физика НПС

Физика — стандартная Godot-физика:

- `CharacterBody3D`;
- гравитация и `MoveAndSlide`;
- тонкая капсула `BodyLine` вместо старой точки;
- поворот по X/Z заблокирован, НПС вращается только вокруг Y;
- спавн ставит НПС на поверхность через реальное смещение низа коллизии;
- высота над поверхностью задаётся `[Export] SpawnHeightAboveSurface`.

Никакого принудительного `SnapToGround` и прямого изменения `GlobalPosition` для отталкивания нет.

## Хитбоксы

`HitboxManager` — отдельный узел. В `TypesOfObjects` перечислены типы:

```text
[имя группы, сцена, скрипт обработки,
 оптимизация позиции, оптимизация проверок,
 номера типов для проверки столкновений]
```

Размеры хитбокса считаются по `MeshInstance3D` из сцены:

- обычный меш — по его AABB;
- сфера — по радиусу и высоте.

Хитбокс — математический OBB: положение, размеры по XYZ и поворот. Пересечения считаются в `HitboxProcessor` через SAT.

Типы в текущей сцене:

```text
Npc        → [0]    // только раздвигание НПС
Bullet     → [2]    // проверяет damage-хитбоксы НПС
NpcDamage  → [0]    // урон в ближнем бою по НПС
```

### Damage-хитбокс

У каждого НПС есть отдельный damage-хитбокс, в 2 раза больше обычного. Только он наносит урон:

- урон от пуль;
- урон в ближнем бою.

Общий хитбокс НПС занимается только раздвиганием.

У damage-хитбокса свой таймер проверки: `CheckIntervalFrames = 50`. У каждого объекта свой `FramesUntilCheck`, начальная фаза смещается, чтобы проверки не приходились всем НПС в один кадр. По этому таймеру идёт урон в ближнем бою.

Пуля проверяет damage-хитбоксы каждый кадр, чтобы попадание срабатывало в момент соприкосновения, а не раз в 50 кадров. Найденное пересечение передаётся в `NpcDamageProcessor` — он наносит урон и вызывает `Consume`, после чего пуля удаляется.

### Оптимизация позиции и проверок

- Позиция хитбокса может обновляться реже, чем визуальная часть.
- Период зависит от глобального FPS и скорости объекта; при скорости меньше `1` — каждый кадр.
- Проверки могут выполняться в момент обновления позиции, каждый кадр или раз в `CheckIntervalFrames`.
- Проверки распределяются через `Parallel.For`; изменение сцены выполняется после этого на главном потоке.

### Расширение по движению

Чтобы объект не проскочил между обновлениями, хитбокс расширяется в сторону движения:

```text
direction = localMovement / max(|x|, |y|, |z|)
extension = framesBetweenUpdates ^ 0.34
Size += abs(direction) * extension
```

Вектор движения переводится в локальные оси хитбокса, поэтому поворот объекта учитывается.

### Раздвигание НПС

НПС не проходят друг в друга только через `HitboxManager`:

- пары одного типа проверяются один раз;
- для пересечения находится минимальный вектор выталкивания;
- каждый НПС смещается на половину этого вектора в противоположные стороны;
- смещение применяется через `MoveAndCollide`.

Физический слой NPC-NPC для этого не включается.

## Урон и цели

- Если НПС заспавнился или потерял цель — ищет ближайшего противника.
- Если получил урон — переключается на того, кто нанёс урон.
- Если у пули нет shooter (`ShooterId = -1`), цель не меняется.
- Каждая пуля хранит `ShooterId` и команду стрелка (`ShooterSquad`).
- Пуля наносит урон только противнику: союзника она пролетает насквозь и не исчезает.
- Ближний бой бьёт только выбранную цель.
- Отталкивание от урона:

```text
direction / max(|x|, |y|, |z|) * damage^0.5
```

Вектор применяется через `MoveAndCollide`.

## Пуля

`Bullet`:

- летит по направлению `Direction`;
- при `Launch` разворачивается так, чтобы `-Z` смотрела по направлению движения;
- каждый кадр проверяет damage-хитбоксы НПС;
- пролетает союзника насквозь, не нанося урона;
- при попадании в damage-хитбокс `NpcDamageProcessor` наносит урон и вызывает `Consume` — пуля удаляется;
- живёт `LifetimeFrames` физических кадров.

## Здоровье и Label `Hp`

`HealthComponent` хранит здоровье, защиту и регенерацию. При любом изменении здоровья — спавн, урон, регенерация, смерть — `Npc.UpdateHealthLabel` сразу записывает значение в Label3D `Hp`, без задержек и накопления.

## FPS

Label `Fps` в `HitboxManager` показывает текущий глобальный FPS:

```text
+/- Fps: {Engine.GetFramesPerSecond()}
```

Обновляется каждый физический кадр.
