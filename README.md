# Practice 3. NpcWar

(Made with Deepseek Harness)

Небольшой проект на Godot 4.7 / C#: НПС воюют командами, а игрок наблюдает за сценой свободной камерой.

## Управление

- `WASD` — полёт по направлению камеры.
- `Shift` — ускорение.
- `Мышь` — обзор.
- `Esc` — отпустить мышь, клик — снова захватить.
- `Z` — показать/скрыть розовые полупрозрачные хитбоксы.

## Архитектура

Иерархия:

```text
EntityManager
├── HitboxManager
├── PhysicManager
│   └── PhysicProjectileManager
└── QueryManager
```

- `EntityManager` — над-система: хранит описания типов, создаёт логические объекты и связывает остальные менеджеры.
- `HitboxManager` — хранит хитбоксы, считает OBB-пересечения через SAT и вызывает поведение объекта.
- `PhysicManager` — создаёт сцену объекта, двигает `CharacterBody3D` по запросам скорости штатной физикой Godot (гравитация, `MoveAndSlide`, столкновения со стенами) и применяет смещения.
- `PhysicProjectileManager` — подинструмент `PhysicManager`: до создания визуала задаёт снаряду ориентацию по траектории, двигает снаряды, считает время жизни и удаляет их. Своего `Entity` у снаряда нет.
- `QueryManager` — принимает векторы скорости и смещения от query-скриптов; снимает положение и поворот с фактического объекта сцены и обновляет хитбоксы с оптимизацией. Здесь же Label `Fps`.

## Описание типа

Типы объектов задаются в `EntityManager.Types` списком `EntityTypeConfig`:

- тип: `Object`, `Projectile` или `Static`;
- название — вместо групп;
- объекты сцены (готовые стены/пол) — списком путей;
- сцена визуала;
- скрипт запросов (только `Object`);
- скрипт поведения;
- класс данных (только `Object`);
- количество кадров жизни (только `Projectile`);
- флаги оптимизации позиции и проверок, интервал проверок, типы для проверки пересечений;
- дополнительные хитбоксы, создаваемые вместе с основным.

## Объект

`Entity` — обычный `Node`, а не `Node3D`. Он не двигается сам: хранит данные, а его query-скрипт считает вектор скорости и поворот и шлёт запросы в `QueryManager`.

- `EntityData` — данные объекта (`RefCounted`). Массивы используются там, где важен номер элемента; списки — где элементы часто добавляются и удаляются.
- `EntityQuery` — один экземпляр на тип: обновляет все объекты типа и отправляет запросы.
- `EntityBehavior` — условия обработки: `OnSpawn`, `OnIntersect`, `OnProjectileHit`, `OnDeath`. Программисту достаточно описать эти условия в наследнике.

## НПС

- `NpcData` — здоровье, защита, регенерация, скорость, урон, интервал атаки, радиус стрельбы. Бывшие компоненты стали свойствами, а купленные интерфейсы и апгрейды хранятся массивами.
- `NpcQuery` — выбор цели, регенерация и выстрелы; считает вектор скорости к цели и поворот, а не координаты. Позиции для наведения читает из фактического тела.
- `NpcBehavior` — раздвигание, ближний бой, получение урона, отталкивание и смерть. Он же обновляет Label3D `Hp` при любом изменении здоровья.
- `NpcManager` — очки команд, спавн в кольцевых секторах, массив слотов и замена погибших. Позиции для выбора цели берутся из `QueryManager`, то есть из фактических тел.

У НПС два хитбокса:

- основной `Npc` — только раздвигание;
- `NpcDamage` — второй тип, который снимает трансформ с того же тела, что и основной, но проверяется раз в 50 кадров и только он наносит урон в ближнем бою.

`Npc.tscn` — `CharacterBody3D` без скрипта. Физическая коллизия — маленькая `SphereShape3D` (радиус `0.02`) в точке ног: она выглядит как точка, но даёт твёрдый контакт с полом и стенами. `PhysicManager` применяет гравитацию и `MoveAndSlide`, поэтому НПС не проваливается и упирается в стены. Хитбоксы снимают уже итоговое положение тела после физики.

## Снаряды и статика

`BulletBehavior` описывает свойства снаряда (`Speed`, `Damage`) и реакцию на попадание. `Bullet.tscn` — тоже только визуал.

- снаряд каждый кадр двигает визуал, а его хитбокс обновляется по оптимизации позиции;
- хитбокс растягивается вдоль движения, поэтому проверки выполняются реже — в момент обновления позиции;
- по противнику урон наносит `NpcBehavior`, после чего снаряд удаляется;
- союзника снаряд пролетает насквозь;
- о статический объект (стену, пол) снаряд разбивается.

Тип `Static` описывает готовые объекты сцены: размеры, положение и поворот считаются по их форме, поэтому пули уничтожаются о стены без отдельных коллизий.

## Физика объекта

- запрос движения — вектор скорости, а не координаты;
- `PhysicManager` применяет гравитацию и `MoveAndSlide`;
- пол и стены — обычные `StaticBody3D`, точечная сфера НПС с ними сталкивается;
- раздвигание и отталкивание — векторы смещения через `MoveAndCollide`;
- хитбоксы снимаются с фактического `CharacterBody3D` уже после физики.

`SeparationRayShape3D` для опоры не используется: это не solid shape, он не создаёт контактов и не держит вес. Поэтому физическая коллизия — минимальная твёрдая сфера в точке ног.

## Хитбоксы

Хитбокс — математический OBB: положение, размеры по XYZ и поворот. Положение и поворот снимаются с фактического объекта сцены (`Source`), поэтому учитывают физику и столкновения. Пересечения считаются в `HitboxProcessor` через SAT.

Текущие типы и проверки:

```text
Npc        → [Npc]          // раздвигание НПС
NpcDamage  → [Npc]          // урон в ближнем бою, раз в 50 кадров
Bullet     → [NpcDamage, Static]
Static     → []             // сам ничего не проверяет
```

Оптимизация позиции живёт в `QueryManager`:

- между обновлениями хитбокс объекта — это swept-OBB: центр ставится в середину отрезка от прошлого центра до текущего, а размер растягивается на длину этого отрезка; весь путь попадает внутрь одного OBB;
- интервал обновления выбирается из минимальной толщины хитбокса цели `L` и её максимальной скорости `V`: `interval = L / (2 * V)`, затем `period = round(FPS * interval)`, но не меньше одного кадра;
- при скорости меньше `1` хитбокс обновляется каждый кадр.

Это даёт гарантию: если цель пересекала путь между обновлениями, то за интервал она сместится не дальше `L / 2`, поэтому её хитбокс всё ещё пересекает swept-путь и будет найден на проверке.

От скорости снаряда интервал не зависит: любой пройденный путь целиком покрывается растянутым хитбоксом. При очень низком FPS, когда один кадр уже больше `L / (2 * V)`, для гарантии нужен дополнительный запас или более частая проверка.

У снарядов включены `OptimizePosition` и `OptimizeChecks`: хитбокс обновляется с этим интервалом и проверяется только в момент обновления — обработок меньше. У НПС оба хитбокса обновляются каждый кадр, а damage-хитбокс проверяется раз в 50 кадров.

## Урон и цели

- НПС ищет ближайшего противника, если цели нет или она погибла.
- Получив урон, переключается на того, кто его нанёс.
- Ближний бой бьёт только выбранную цель.
- Отталкивание: `direction / max(|x|, |y|, |z|) * damage^0.5`, применяется вектором смещения через `MoveAndCollide`.
- По своим урон не проходит.

## Метки

- `Fps` в `QueryManager`: `+/- Fps: {Engine.GetFramesPerSecond()}` каждый физический кадр.
- `Npcs` в `NpcManager`: количество не-null элементов массива НПС.
- `Hp` у каждого НПС: обновляется сразу при спавне, уроне, регенерации и смерти.
